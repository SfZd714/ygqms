## 故事1：XMagital 工业知识库系统
**适用问题**：介绍一个 AI 项目 / 实习中做了什么 / 你最熟悉的项目。

- S：工业领域通用大模型缺乏企业私有设备知识，传统 RAG 固定切片会破坏故障因果链。
- T：在团队协作项目中负责知识库子系统后端三条核心链路。
- A：设计知识注册流水线、三路混合检索、知识图谱根因分析和离线韧性层。
- R：测试环境端到端跑通；Token、召回率、响应时间等指标均有小规模测试口径。

## 故事2：RAG 混合检索精度优化
**适用问题**：如何提升 RAG 检索效果 / 遇到过什么技术难题。

- S：单路向量检索在设备型号、精确编号查询中容易混淆。
- T：提升检索召回和精确编号命中。
- A：设计向量检索、pg_trgm 关键词检索、ILIKE 精确匹配三路并行，用 RRF 替代原始分数加权，再用 LLM Reranker 精排。
- R：30 个工业问题测试中 Recall@5 从 19/30 提升到 23/30；10 个编号问题错误从 4 个降到 1 个。

## 故事3：LLM 幻觉抑制与图谱验证
**适用问题**：如何处理 LLM 幻觉 / 知识图谱有什么价值。

- S：工业故障场景对准确性要求高，LLM 可能编造不存在的故障原因或危险操作。
- T：让回答能够被真实文档和因果链约束。
- A：抽取实体关系形成图谱；顺向因果链与方案路径用 BFS 分层扩散，反向根因候选追溯用 DFS + 路径级 visited 回溯并在末尾去重；如果要保留每条独立路径，再用 `enumerateRootCausePaths`，深度惩罚过滤深层噪声；矛盾只标记，不自动修改。
- R：对知识库覆盖的设备故障，回答可溯源、可验证，减少纯生成式幻觉。

## 故事4：三合一 LLM 抽取优化
**适用问题**：如何优化 LLM 调用成本 / Prompt Engineering 经验。

- S：原方案实体抽取、三元组抽取、关系分类分三次调用，重复输入原文，Token 消耗高且实体命名不一致。
- T：降低调用成本并提高结构一致性。
- A：把三个子任务合并为一次结构化 JSON 输出，加入 zod 校验和实体引用检查，失败重试。
- R：Token 从约 3200/段降到含重试约 1600/段，对外口径约节省 54%；单次输出内实体引用一致。

## 故事5：高可用 AI 服务架构
**适用问题**：如何设计可靠 AI 服务 / 远程 API 不稳定怎么办。

- S：工厂内网场景下远程 API 可能受网络、合规、限流影响。
- T：保证嵌入服务失败时系统可控降级。
- A：本地 BGE-M3 ONNX 优先，失败或超负载时切远程 API；远程连续失败触发熔断；熔断器用时间戳按需检查而非 setTimeout。
- R：本地嵌入单条约 40-60ms，远程 API 约 200-400ms；避免进程重启后熔断器死锁。

## 故事6：工业文档分块难题
**适用问题**：项目最大挑战 / 怎么做文档切分。

- S：工业文档的故障处理链条常跨多个自然段，固定切片会切断上下文。
- T：既保证 LLM 抽取上下文完整，又保证检索粒度合适。
- A：拆成两阶段分块：大块用于 LLM 抽取，小块用于数据库检索；标题层级感知处理章节、编号、附录。
- R：减少三元组残缺，提高故障因果链保留能力。

## 故事7：华为 UART 通信协议设计
**适用问题**：独立攻坚经历 / 华为具体做了什么。

- R：模块顺利完成并通过联调；形成独立负责模块全流程的工程习惯。

## 故事9：蓝桥杯 AI 赛 FastGPT 简历评估智能体
**适用问题**：智能体/工作流项目经验 / 如何保证 LLM 输出稳定。

- S：蓝桥杯 AI 赛要求构建能自动评估简历的智能体，不能让大模型直接随意打分。
- T：实现从简历解析、语义分析、量化评分到结果写入的稳定流程。
- A：基于 FastGPT 设计分层解耦架构：function_call 负责结构化提取，AI 对话节点负责语义判断，代码节点负责定量评分，知识库保存评分规则和岗位要求。
- R：结构化提取准确率从约 80% 提升到 95% 以上；Prompt 从约 800 字降到约 200 字；最终获得蓝桥杯 AI 赛陕西省二等奖。
