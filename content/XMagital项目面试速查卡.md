# XMagital项目面试速查卡

> 面试前 10 分钟快速复习。核心目标：口径统一、数字可解释、职责边界清楚。

## 一句话项目介绍
我在和利时实习期间，参与 XMagital 工业知识库系统，负责知识库子系统后端三条核心链路：文档如何变成知识入库、用户问题如何检索出答案、设备报警如何追溯根因。

## 30秒版本
XMagital 是一个面向工业场景的企业知识库系统，用来解决通用大模型缺乏企业私有设备知识、传统 RAG 固定切片破坏故障因果链的问题。我在知识库子系统中负责三条核心后端链路：知识注册流水线、RAG 混合检索问答、知识图谱推理与根因分析，并参与共用离线韧性层设计。项目里我重点做了两阶段分块、三路混合检索、BFS 顺向因果链与 DFS 回溯反向根因追溯、时间戳熔断器等工程优化。

## 三条主线
1. **不是只会接模型**：做的是从文档解析、分块、LLM 抽取、向量入库，到三路检索、RRF 融合、Reranker，再到图谱构建、根因分析的完整后端链路。
2. **不是照单全收 AI 代码**：两阶段分块、RRF 替代原始分数加权、反向根因追溯从 BFS+永久 visited 改为 DFS+路径级 visited 回溯、时间戳替代 setTimeout 熔断器，都是测试后做出的工程判断。
3. **能说清楚测的是什么**：Token、召回率、响应时间等数字都有测试方法和边界，不把小规模测试说成生产长期指标。

## 遍历算法口径（易被问，别说错）
| 功能 | 函数 | 算法 |
|---|---|---|
| 顺向因果链构建 | `buildCausalChain` → `bfsTraverse` | BFS + 永久 visited |
| 方案路径搜索 | `findSolutionPaths` | BFS + 永久 visited |
| 反向根因候选追溯 | `findRootCauseCandidates` | DFS + 路径级 visited 回溯 + 末尾去重 |
| 根因独立路径枚举（Noisy-Or 证据聚合） | `enumerateRootCausePaths` | DFS + 路径级 visited 回溯 |

一句话：BFS 回答「影响到哪些节点」，DFS 候选追溯回答「有哪些候选根因」，DFS 路径枚举回答「有哪几条独立路径」。三者并存，不是替换关系。
